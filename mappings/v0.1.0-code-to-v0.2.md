# De/Para v0.1.0 técnica -> PIBRAS v0.2 draft

Este arquivo reconcilia os artefatos atuais com o alvo v0.2. A regra é evoluir sem quebrar consumidores existentes.

## Resumo

| Área | v0.1.0 técnica | v0.2 draft | Decisão |
|---|---|---|---|
| Código do imóvel | `property.code` | `external_ids[]` | Manter `code` como compatibilidade; adicionar `external_ids[]` como alvo. |
| Dinheiro | `Money { amount, currency }` | `Money { amount, currency }` | Preservar. `_brl` fica restrito a exportadores. |
| Identidade física | `Building -> Unit -> Property` | `Building -> Unit -> Property` | Preservar. Deduplicação ocorre em `Unit`. |
| Proprietários | `Owner` + `property_owners` | `Party` + `Ownership` | Adicionar alvo v0.2; manter compatibilidade. |
| Geografia | `Neighborhood` | `Geography` | `Geography` vira superset; `Neighborhood` permanece subtipo/compatibilidade. |
| Exposição | `ExposureRule` + `field_visibility` | `ExposurePolicy` | Adicionar política default-deny; mapear regras antigas. |
| Ingestão | `ingestion_record` + `pending_change` | `ImportSource` + `ImportBatch` + `ImportMapping` + trilha bruta | Manter trilha bruta; adicionar metadados de orquestração. |
| LGPD | campos em `Owner` e auditoria genérica | controller/processor + `DataSubjectRequest` | Adicionar entidades e campos mínimos. |
| Conformidade | exemplo único | `tests/golden/` | Adicionar fixtures positivas e negativas. |

## Identificadores externos

### Atual

```json
{
  "code": "MB18495",
  "provenance": {
    "source_system": "mbras_internal",
    "source_record_id": "MB18495"
  }
}
```

### Alvo

```json
{
  "code": "MB18495",
  "external_ids": [
    {
      "namespace": "mbras",
      "key": "property_code",
      "value": "MB18495"
    }
  ]
}
```

`code` permanece durante a janela de compatibilidade. Implementações novas devem preferir `external_ids[]`.

## Money

Campos como `asking_price_brl`, `minimum_price_brl`, `condominium_fee_brl` e `iptu_brl` não são canônicos.

### Canônico

```json
{
  "asking_price": {
    "amount": 1750000000,
    "currency": "BRL"
  }
}
```

## Unit como âncora de deduplicação

`Unit` deve receber metadados explícitos de dedupe:

```txt
dedupe_key
normalized_address_key
area_signature
duplicate_of_unit_id
dedupe_confidence
dedupe_review_state
```

Thresholds v0.2:

```txt
auto_merge_threshold: >= 0.95
manual_review_band: 0.75 até 0.95
auto_reject_threshold: < 0.75
```

| `owner.name` | `party.name` |
| `owner.legal_name` | `party.legal_name` |
| `owner.tax_id` | `party.tax_id` |

|---|---|
| `neighborhood.canonical_name` | `geography.canonical_name` |
| `neighborhood.aliases` | `geography.aliases` |
| `neighborhood.city` | `geography.city` |

## ExposureRule -> ExposurePolicy

| v0.1.0 | v0.2 |
|---|---|
| `exposure_level` | `exposure_policy.exposure_level` |
| `field_visibility` | regras `allow`/`deny` por campo |
| `allowed_channels` | `allowed_channels` |
| `requires_approval` | `requires_approval_for` |
| `price_display` | regra por campo `asking_price`/`display_price` |
| `address_display` | regra por campos `address.*` |

Semântica v0.2:

```txt
default deny para campos sensíveis, escrita, exportação e publicação;
deny explícito vence allow;
regra mais específica vence default;
needs_approval bloqueia envio até aprovação;
toda decisão retorna reason_code e applied_rule_ids.
```

## Ingestão

`ImportBatch` representa a operação de importação. `ingestion_record` continua guardando payload bruto. `pending_change` continua guardando diffs que precisam de revisão.

```txt
ImportBatch
  -> ingestion_record[]
  -> pending_change[]
  -> audit_log[]
```

## Critérios de aceite v0.2

Uma migração só está completa quando:

- o exemplo v0.1.0 ainda valida;
- pelo menos um exemplo v0.2 com `external_ids[]` valida;
- `ExposurePolicy` tem fixture default-deny;
- `DataSubjectRequest` tem fixture válida;
- `Unit` tem fixture de candidato de dedupe;
- README e VERSIONING apontam o status correto.
